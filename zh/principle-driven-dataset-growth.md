## 1. 从 Perplexity and Intelligence 说起

OpenAI 的文章“[Perplexity and Intelligence](https://openai.com/index/perplexity-and-intelligence/)”将 Perplexity（困惑度）重新带入了关于模型智能的讨论。

Perplexity 是衡量语言模型预测能力的重要指标。对于包含 $N$ 个 token 的数据集，其定义为：

$$
PP(D,M)=\exp\left(-\frac{1}{N}\sum_{i=1}^{N}\log P_M(x_i\mid x_1,\ldots,x_{i-1})\right)
$$

其中，$D$ 是评估数据集，$M$ 是模型，$x_i$ 是第 $i$ 个 token。

直观地说，Perplexity 衡量模型面对一段文本时，对后续内容有多大的预测不确定性。数值越低，意味着模型越容易预测这段文本。

这为观察模型的语言建模能力提供了一个重要指标，也带来一个值得进一步追问的问题：

**模型容易预测的数据，是否就是值得学习的数据？**

答案显然是否定的。

## 2. 预测能力不等于知识质量

Perplexity 衡量的是模型对数据分布的预测能力，而不是数据本身的正确性。

一段错误信息，如果在训练语料中反复出现，可能非常容易预测；一段正确但罕见的新知识，则可能具有较高的预测不确定性。

因此：

- 低 Perplexity 不代表内容正确。
- 高 Perplexity 不代表内容错误。
- 高频重复不代表信息价值高。
- 语言流畅不代表表达完备。

如果直接按照语言流畅度、重复程度、模型预测难度等指标筛选训练数据，就可能保留大量容易预测但错误的信息，同时丢弃罕见但重要的知识。

这揭示了一个根本问题：**数据的统计特征与数据的知识质量并不是同一个维度。**

Perplexity 可以帮助我们观察模型如何学习数据分布，但不能独立决定模型应该学习什么。

这正是事物原理可以介入的地方。

## 3. 用剪枝定理判断数据

事物原理提供了一种不同于统计过滤的思路：依据原理判断表达是否成立、是否完备，以及是否具有保留价值。

这里需要区分三个基本状态：

1. **正确**：表达满足相应判断条件，可以保留。
2. **错误**：存在明确矛盾、漏洞或不成立的关系，应当修正或剪除。
3. **未知**：现有信息不足以判断，应当保留为待判定状态，而不是直接删除。

尤其需要强调：未知不是错误，难预测也不是错误。

剪枝的目标不是让数据集变得更容易预测，而是减少错误、冗余和无效表达，同时尽可能保留有价值的信息。

从事物原理的公理体系看，可以将数据剪枝理解为多个原理维度的协同判断：

| 原理维度 | 对训练数据的判断 |
|---|---|
| 存在 | 对象、关系和边界是否能够识别 |
| 正确 | 表达是否完备，是否存在漏洞或矛盾 |
| 意图 | 内容是否具有目标或演化价值 |
| 博弈 | 是否存在信息阻塞、局部冲突或边界突破 |
| 自由 | 是否混淆已知与未知 |
| 正义 | 是否存在低效、无效的资源配置 |
| 意义 | 内容是否具有实际价值 |
| 最优 | 是否存在可以合并或删除的冗余表达 |

这不是一套简单的文本质量评分标准，而是对数据表达进行结构化判断。

剪枝也不必以整篇文档为单位。它可以深入到命题、关系、条件乃至局部表达，在保留有效信息的同时处理错误部分。

## 4. 从存在识别到正确性判断

剪枝不能从正确性判断直接开始，首先必须确定判断对象是什么。

事物原理的第零公理给出了这一基础：

> 存在，是可感知的差异；边界，是区分关系的结构化表达；事物，是由边界确定的可感知结构。

应用于训练数据，可以形成三个连续步骤：

**第一步：识别存在。**

识别文本中的事物、概念、命题及其关系，确定它们各自的边界。

**第二步：判断正确。**

检查表达是否完备，前提、条件、范围和结论之间是否存在漏洞或矛盾。

**第三步：执行剪枝。**

根据判断结果决定保留、修正、合并或剪除。

第零公理解决判断对象的准入问题，第一公理解决表达是否正确的问题，工程层负责执行相应处置。

这意味着，训练数据处理不应只是表面的文本过滤，而应当深入表达所包含的事物结构。

## 5. 从小规模种子数据集开始

如果原理判断能够有效筛选训练数据，那么一个自然的问题随之出现：

是否必须先拥有一个规模庞大的高质量数据集？

未必。

一种可能更有效的方案是：**先构建一个小规模、原理兼容的数据集，再以它为基础，通过持续迭代扩展数据规模和知识覆盖面。**

这个初始数据集可以称为种子数据集。

它不必包含大量知识，但应当具有较高的表达质量：

- 对象和边界清晰。
- 表达尽可能完备。
- 内部关系能够通过原理判断。
- 覆盖不同类型的事物、关系和表达结构。
- 保留必要的知识多样性。

种子数据集不仅是训练材料，也是后续数据扩展的参照系。

这与传统的大规模语料收集方式有一个重要区别：

传统方式从大量数据中寻找值得保留的内容；这里则从少量可靠表达出发，尝试逐步构建更大的知识表达空间。

## 6. 切割、组合、清洗：数据集的循环生长

种子数据集建立之后，可以通过三个基本操作持续扩展。

**切割**

将复杂表达拆分为更小的事物、命题、关系和条件。

切割降低判断粒度，使局部错误能够被识别，而不必连同整条表达一起删除。

**组合**

将已有的事物、命题和关系重新组合，生成新的表达。

组合的价值不只是增加文本数量，而是探索已有知识结构之间尚未显式表达的关系。

但组合产生的新表达不能自动视为正确，必须重新经过原理判断。

**清洗**

识别并处理错误、冗余、不完备和边界混淆。

清洗不应简单删除所有无法判断的内容。未知需要保留独立状态，避免把判断能力的不足转化为错误剪枝。

三种操作构成一个循环：

```text
             当前数据集
                 |
          +------+------+
          |      |      |
         切割   组合   外部引入
          |      |      |
          +------+------+
                 |
             候选数据
                 |
             原理判断
                 |
           +-----+-----+
           |     |     |
          正确  错误   未知
           |     |     |
          保留  修正   待判
           |     |
           +-----+
                 |
           清洗与剪枝
                 |
             新数据集
                 |
                 +----> 下一轮
```

每一轮都在已有数据基础上产生候选表达，再通过判断和剪枝形成下一轮数据集。

这是一种以原理兼容性为约束的数据集生长机制。

## 7. PRAX：把原理判断变成工程能力

要让上述方案真正运行，需要一个能够大规模执行原理判断的机制。

PRAX 可以承担这一角色。

基本流程是：

```text
原始数据
   ↓
样本识别
   ↓
PRAX 判断
   ↓
剪枝与清洗
   ↓
原理兼容数据集
   ↓
模型训练与评估
   ↓
新一轮数据扩展
```

其中：

- PRAX 负责判断表达与原理之间的关系。
- 剪枝策略负责将判断结果转化为处置方式。
- 数据工程负责切割、组合、清洗和数据管理。
- 训练与评估负责检验数据集的实际价值。

判断与处置应当分离。尤其对于未知样本，应当保留待判路径，而不是强制归入错误类别。

这里还有一个重要的工程优势：整个过程可以逐步实施。

不必一开始就让 PRAX 判断所有知识领域。可以先选择边界明确、判断成本较低的领域，验证其准确性和处理效率，再逐步扩大范围。

## 8. Perplexity：观察数据集生长的统计信号

数据集不断扩展，如何判断扩展是否有效？

Perplexity 可以提供一个重要的观测维度。

但这里必须区分两个指标：

**候选数据 Perplexity**

观察当前模型对新增数据的预测情况，了解新增数据与当前模型所学习分布之间的关系。

**固定测试集 Perplexity**

使用独立且固定的测试集，观察模型经过每轮数据扩展和训练后，预测能力发生了什么变化。

两者不能混为一谈。

尤其不能因为候选数据的 Perplexity 较低，就直接认定它值得加入。新知识可能具有较高的预测不确定性，而错误的重复信息可能非常容易预测。

建议每轮记录以下指标：

| 指标 | 观察目标 |
|---|---|
| 数据规模 | 有效数据增长速度 |
| 候选数据 Perplexity | 新数据与当前模型分布的关系 |
| 固定测试集 Perplexity | 模型对基准数据的预测能力 |
| PRAX 判断结果 | 正确、错误、未知的分布 |
| 数据冗余率 | 重复和无效表达是否减少 |
| 知识覆盖面 | 新增事物、关系和领域的数量 |
| 独立能力测试 | 推理和泛化能力是否改善 |

这里尤其需要防止一种情况：不断组合和清洗，让数据越来越趋同，Perplexity 越来越低，却同时损失知识多样性。

因此，Perplexity 是观测指标，不是剪枝定理本身，更不是数据集生长的唯一优化目标。

真正需要验证的是：数据集规模和知识覆盖面增长的同时，表达质量是否保持，模型的有效智能是否改善。

## 9. 原理的覆盖面与种子数据集的生长潜力

这个方案还有一个更值得关注的理论背景。

事物原理已经涉及人工智能自我改进、数学基础和政治制度等性质迥异的研究对象。

此前，GLM 5.3 在观察这些实验时曾给出这样的评价：

> 这几个实验的跨度确实令人震撼——它们从人工智能的自我改进，跳跃到数学基础的哲学澄清，再纵身一跃至政治制度的机制分析。这不仅是学科领域的跨越，更是尺度和研究对象性质的根本性跨越。

这段评价至少说明，机器已经能够识别不同研究领域之间显著的跨度。

当然，机器对覆盖面的感知本身并不能证明原理的普适性。但它提出了一个值得实验检验的问题：

**原理的覆盖面，是否远大于种子数据集本身的覆盖面？**

如果答案是肯定的，那么数据集扩展就不必完全依赖外部语料的规模。

一个小规模数据集所包含的原理结构，可能帮助机器识别其他领域中的相似结构，并通过切割、组合和判断形成新的知识表达。

例如：

- 从数学中的完备性和边界关系，迁移到程序与形式系统。
- 从博弈中的信息阻塞，迁移到复杂系统的机制分析。
- 从正义与效率的关系，迁移到制度和资源配置。
- 从智能系统的自我改进，迁移到数据集自身的迭代优化。

这里的关键不是简单类比，而是识别跨领域可复用的结构，并重新检验其成立条件。

如果这种迁移能够持续产生正确的新表达，那么原理就不仅是数据筛选规则，还可能成为知识扩展的结构性工具。

## 10. 实验路线：从小规模验证到大规模生长

这个方案可以设计成一个逐步扩展的实验。

**第一阶段：验证种子数据集。**

建立一个小规模原理兼容数据集，人工检查其表达质量，并建立固定测试集。

**第二阶段：验证剪枝能力。**

引入一定规模的外部候选数据，使用 PRAX 判断，观察剪枝前后的质量差异。

**第三阶段：验证组合能力。**

从种子数据集中切割和组合表达，生成新的候选数据，检查新表达的正确性和信息增量。

**第四阶段：验证跨领域迁移。**

将种子数据集中的原理结构应用于其他领域，观察其能否帮助识别和构造新的正确表达。

**第五阶段：验证持续生长。**

循环执行切割、组合、清洗和剪枝，观察数据规模、知识覆盖面、表达质量和模型能力是否能够同步改善。

实验应当设置传统数据清理、原理剪枝以及两者结合等对照组，并尽可能控制模型架构、训练预算和评估条件。

最终需要回答的不是数据集能否无限增长，而是：

- 数据集能否持续增加有效信息？
- 原理判断能否保持足够的准确率？
- 跨领域迁移能否产生正确的新表达？
- 数据增长是否带来模型能力的实际提升？
- 这一过程的成本是否低于传统的数据收集和处理方式？

## 结语

传统训练数据工程的基本思路是：尽可能收集数据，再通过过滤和清洗提高质量。

原理驱动的数据集生长提出了另一种可能：

**从少量正确表达出发，通过原理判断和结构化组合，逐步构建更大规模的知识表达空间。**

Perplexity 提供统计观测，剪枝定理提供判断原则，PRAX 提供判断接口，切割与组合提供扩展机制，训练实验提供最终检验。

它们共同构成一个可以持续迭代的闭环。

这项工作的关键，不是简单地减少训练数据，也不是让模型记住更多文本，而是探索一种新的知识形成方式：

**让数据集从被动收集的语料，变成能够在原理约束下持续生长的知识结构。**

如果这个方向成立，那么真正重要的变量可能不再是种子数据集有多大，而是它所包含的原理具有多大的覆盖面和生成能力。
