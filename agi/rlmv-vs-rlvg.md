# RLMV vs RLVG 方案对比分析

## 一、方案概览

| 维度 | [RLMV](./rlbv.md) | [RLVG](./rlvg.md) |
|---|---|---|
| **全称** | Reinforcement Learning with Multi-tier Verification | Reinforcement Learning with Latent Geometric Verification |
| **核心理念** | 全集分层 + 分层奖励 + 工程闭环修补 | 隐空间几何验证 + 白盒损失函数 + 原理闭合 |
| **域判定方式** | 外挂判定器 D(x)（神经网络分类器），温度缩放校准 | 静态几何超平面坐标投影，SVD 分解语义子空间 |
| **奖励机制** | 分层奖励 R₂/R₁/R₃ + 条件化软触发 + 解耦归一化 | 几何损失 L_geom + 原点坍缩 L_orig + GDPO 主损失 |
| **B₂ 处理** | 语义熵一致性检测（K=8 采样，阈值 0.7） | 首字熔断（D-latent > 0.4 即扼杀解码） |
| **B₃ 处理** | Brier 分数奖励 + UL 惩罚 | 隐空间原点几何坍缩 L_orig |
| **防御黑客** | 五重防御（隐藏测试集、结构化输出、长度惩罚、格式验证、KL 正则化） | 事前定点清除：Loss 中惩罚向作弊轴偏移的能量 |
| **标注依赖** | 每域 >=2000 条确定性标签 + 黄金集 >=500 条 | 零文本标签，仅需少量基准矩阵提取语义基底 V |
| **原理定位** | 工程闭合（承认域划分为经验组件） | 原理完备（声称隐空间几何坐标完成闭合证明） |

---

## 二、域判定机制对比

### RLBV v0.4 的判定器 D(x)

- **方式**：训练独立的神经网络分类器 D(x)，输出 (域标签, 置信度)
- **校准**：温度缩放 T，验证集最小化 NLL，Brier <= 0.1 后冻结
- **漂移处理**：周期性重校准（每 M=500 步重估温度 T）
- **风险**：判定器与策略共变导致判定边界逐渐失效（已修补：周期性重校准）
- **复杂度**：需额外训练一个分类器，依赖标注数据

### RLVG 的几何投影判定

- **方式**：对 Transformer 前 L_early=4 层隐藏状态做 SVD，分解出 V_rule 和 V_logic 正交子空间，通过投影积分 P_rule(x) 和 P_logic(x) 判定
- **校准**：声称"零风险（终身免校准）"——因为 SVD 分解是数据驱动的静态操作
- **漂移处理**：理论上无需校准（几何结构由数据分布决定）
- **风险**：SVD 分解依赖训练数据的静态统计特性，策略分布漂移后子空间可能失效
- **复杂度**：需访问前向传播中间层，需 SVD 分解计算

### 判定机制对比总结

| 对比项 | RLBV D(x) | RLVG 几何投影 |
|---|---|---|
| **校准需求** | 需要（温度缩放 + 周期性重校准） | 声称无需（但依赖 SVD 稳定性假设） |
| **漂移鲁棒性** | 有显式监控和重校准机制 | 未讨论策略漂移对几何子空间的影响 |
| **实现复杂度** | 额外训练一个分类器 | 需修改前向传播获取中间层 + SVD |
| **可解释性** | 黑盒分类器（有置信度输出） | 白盒（投影坐标可解释） |
| **泛化能力** | 依赖分类器训练质量 | 依赖 SVD 子空间是否覆盖新分布 |

## 三、奖励/损失机制对比

### RLBV v0.4 的分层奖励

总奖励公式：

R = w₂·R₂ + σ(R₂-τ)·(w₁·R₁ + w₃·R₃ + R_div) - α·BV - β·UL

- **R₂**（B₀/B₁）：验证器奖励 × 覆盖率
- **R₁**（B₂）：语义熵一致性奖励
- **R₃**（B₃）：Brier 分数
- **R_div**：采样多样性惩罚
- **BV**：域判定错误率惩罚
- **UL**：B₃ 未拒答比例惩罚

关键机制：解耦归一化（z-score）、条件化软触发（sigmoid 控制 C₁/C₃ 逐步生效）、奖励预热（前 W 步仅用主奖励）

### RLVG 的几何损失

总损失函数：

L_total = L_GDPO + λ_geom·L_geom + λ_orig·L_orig

- **L_geom**：反奖励黑客隐层惩罚——在投机轴子空间 V_hack 上压制早期隐向量的作弊偏移
- **L_orig**：B₃ 域原点几何坍缩——迫使有效语义轴坐标能量向原点坍缩，吐出极简拒答文本

### 奖励/损失机制对比总结

| 对比项 | RLBV v0.4 | RLVG |
|---|---|---|
| **奖励分解** | 显式分层（R₁/R₂/R₃），每域独立奖励函数 | 统一损失函数，通过几何项间接控制 |
| **多奖励协调** | 解耦归一化 + 条件化软触发 + 奖励预热 | 通过 λ_geom / λ_orig 超参数调节 |
| **B₃ 拒答控制** | Brier 分数奖励 + UL 惩罚 + 拒答阈值调控 | 原点几何坍缩 L_orig（迫使输出极简） |
| **黑客防御** | 五重防御（事后拦截为主） | 事前定点清除（Loss 层面直接惩罚作弊轴） |
| **可调节性** | 7+ 个超参数（w₁/w₂/w₃/α/β/τ/λ_div） | 2 个超参数（λ_geom=0.15, λ_orig=0.25） |
| **理论保证** | 工程经验调参 | 声称几何约束提供理论保证 |

## 四、B₂ 一致性处理对比

### RLBV v0.4

- **方法**：语义熵——K=8 采样，句子嵌入余弦相似度矩阵的特征值熵
- **阈值**：一致性 >= 0.7 才给正奖励
- **特点**：需要完整解码后计算，计算成本高

### RLVG

- **方法**：首字熔断——在 t=1 时提取 K=8 分支的隐藏状态，计算隐空间几何方差 D-latent
- **阈值**：D-latent > 0.4 即刻扼杀后续解码
- **特点**：仅需首 Token 计算，计算成本极低，但可能过早截断有效推理

### B₂ 处理对比总结

| 对比项 | RLBV v0.4 | RLVG |
|---|---|---|
| **计算时机** | 完整解码后 | 首 Token 生成时 |
| **计算成本** | 高（需等 8 个分支完全解码） | 极低（首字即决断） |
| **误杀风险** | 较低（基于语义熵的全局度量） | 较高（首字离散度大不一定代表推理错误） |
| **适用场景** | 需要完整推理链的任务 | 适合快速筛选、算力受限场景 |

## 五、防御与安全对比

### RLBV v0.4 的五重防御

1. 隐藏测试集（训练/评估 80/20 不重叠）
2. 结构化输出（JSON/schema 强制解析）
3. 长度惩罚
4. 格式验证
5. KL 正则化

### RLVG 的几何防御

- **事前定点清除**：在 Loss 中直接惩罚向作弊轴 V_hack 偏移的能量
- **优势**：在优化层面直接消除作弊动机，而非事后拦截
- **风险**：V_hack 子空间的定义依赖先验知识，可能遗漏新型攻击面

### 防御机制对比总结

| 对比项 | RLBV v0.4 | RLVG |
|---|---|---|
| **防御哲学** | 事后拦截 + 多层兜底 | 事前消除 + 几何约束 |
| **覆盖范围** | 5 个独立防御层 | 1 个几何惩罚项 |
| **攻击面** | 覆盖已知攻击模式 | 依赖 V_hack 子空间定义的完整性 |
| **可组合性** | 可与 RLVG 的几何防御互补 | 可与 RLBV 的五重防御互补 |

## 六、数据与标注依赖对比

| 对比项 | RLBV v0.4 | RLVG |
|---|---|---|
| **标注需求** | 每域 >=2000 条 + 黄金集 >=500 条 | 零文本标签，仅需基准矩阵 |
| **标注成本** | 高（需人工标注 + 交叉验证） | 低（无标注） |
| **验证器** | 需要外部验证器 V(x,y) | 不需要外部验证器 |
| **SFT 阶段** | 需要混合数据训练 | 未明确说明 SFT 需求 |
| **实际可行性** | 工程上成熟但标注成本高 | 理论优美但"零标签"声明需验证（SVD 仍需有标签的预训练数据） |

> **关键质疑**：RLVG 声称"零文本标签"，但 SVD 分解需要的"基准矩阵"本质上仍来自有标签数据。如果预训练模型已经在有标签数据上训练过，那么"零标签"只是将标注成本前移到预训练阶段，而非真正消除。

## 八、缺陷与风险对比

### RLBV v0.4 已闭合的 20 条缺陷

| 层级 | 缺陷 | 修补机制 |
|---|---|---|
| 奖励层 | 验证器噪声 | PGFC 校正 |
| 奖励层 | 多奖励坍缩 | 解耦归一化 + 条件化软触发 |
| 奖励层 | 长度方差 | VL Norm |
| 奖励层 | 奖励尺度漂移 | 预热 ramp-up |
| 奖励层 | 中间步骤不可验证 | Step-V 步骤级验证器（可选） |
| 判定层 | 判定器未校准 | 温度缩放 + Brier 冻结 |
| 判定层 | 域分布漂移 | 域占比监控 + 自动补样 |
| 判定层 | 判定器-策略共变 | 周期性重校准 |
| 梯度层 | 梯度范数波动 | 全局裁剪 |
| 梯度层 | π_ref 漂移 | 周期性快照或 EMA 更新 |
| 算子层 | KL 估计偏差 | 双估计器交叉验证 |
| 算子层 | 采样多样性坍缩 | 自适应温度 + 多样性惩罚 |
| 防御层 | 奖励黑客 | 五重防御 |
| 防御层 | 灾难性遗忘 | MMLU 回归测试 |
| 防御层 | 验证器版本漂移 | 版本锁定 + 回放缓冲 |
| 闭环层 | 在线监控缺失 | 指标异常自动回调表 |
| 数据层 | 隐藏测试集泄漏 | 80/20 不重叠 |
| 数据层 | 结构化输出绕过 | JSON/schema 强制解析 |

### RLVG 未讨论/可能存在的风险

| 风险类别 | 具体问题 | RLBV 是否有对应机制 |
|---|---|---|
| **SVD 子空间漂移** | 策略分布变化后 V_rule/V_logic 子空间可能失效 | RLBV 有域占比监控 + 自动补样 + 判定器重校准 |
| **SVD 计算开销** | 大规模模型前向传播提取中间层 + SVD 分解的计算成本 | RLBV 的 D(x) 是轻量级分类器，推理成本低 |
| **V_hack 子空间定义** | 作弊轴的先验定义可能不完整 | RLBV 的五重防御覆盖更宽泛 |
| **首字熔断误杀** | D-latent > 0.4 可能误杀需要发散思维的有效推理 | RLBV 的语义熵基于完整解码，误杀率更低 |
| **"零标签"可行性** | SVD 基准矩阵的来源未明确，可能仍需标注数据 | RLBV 明确标注需求和流程 |
| **B₃ 原点坍缩的副作用** | 强制能量坍缩可能损害 B₃ 域的有效输出质量 | RLBV 的 Brier 分数奖励更温和 |
| **收敛性证明** | 声称"原理闭合"但缺乏形式化证明 | RLBV 明确声明为"工程闭合"，不声称原理完备 |

## 九、互补性分析

两个方案并非互斥，存在显著的互补空间：

| 互补维度 | RLBV 可借鉴 RLVG 的 | RLVG 可借鉴 RLBV 的 |
|---|---|---|
| **判定层** | -- | 域分布监控 + 自动补样、判定器周期性重校准 |
| **奖励层** | 几何损失 L_geom 可作为 R₂ 的补充惩罚项 | 解耦归一化、条件化软触发、奖励预热 |
| **B₂ 处理** | 首字熔断可作为语义熵的快速预筛选 | 语义熵的完整解码一致性检查 |
| **防御层** | 五重防御可作为几何防御的兜底 | 事前几何惩罚可作为五重防御的增强 |
| **B₃ 处理** | 原点坍缩可作为 Brier 分数的补充 | Brier 分数奖励、UL 惩罚、拒答阈值调控 |
| **监控层** | -- | 在线监控闭环、指标异常自动回调表 |
| **数据层** | -- | 隐藏测试集 80/20 不重叠、结构化输出 |

### 融合方案建议

一个潜在的融合架构（RLBV+RLVG Hybrid）：

1. **判定层**：用 RLVG 的几何投影做快速预分类（前 4 层），用 RLBV 的 D(x) 做精确分类（全层），两者交叉验证
2. **奖励层**：GDPO 主损失 + RLBV 分层奖励 + RLVG 的 L_geom（几何黑客惩罚）+ L_orig（B₃ 坍缩）
3. **B₂ 处理**：首字熔断（RLVG）做快速筛选 + 语义熵（RLBV）做精确验证
4. **防御层**：RLVG 的事前几何惩罚 + RLBV 的五重事后防御
5. **监控层**：RLBV 的完整监控闭环（RLVG 未涉及）

## 十、总结评价

| 维度 | RLBV v0.4 | RLVG |
|---|---|---|
| **工程成熟度** | 高（20 条缺陷全部闭合，有完整的训练流程和监控闭环） | 中（核心机制清晰，但缺乏完整的训练流程和监控设计） |
| **理论严谨性** | 中（明确声明为"工程闭合"，不声称原理完备） | 声称"原理完备"，但"零标签"和"终身免校准"声明需进一步验证 |
| **实现复杂度** | 中（需训练 D(x) + 多层奖励协调） | 高（需修改前向传播 + SVD + 几何损失） |
| **标注成本** | 高（每域 >=2000 条） | 声称零标签（但实际依赖预训练数据） |
| **计算效率** | 中（语义熵需完整解码） | 高（首字熔断节省算力） |
| **防御强度** | 强（五重防御 + 闭环监控） | 中（几何惩罚覆盖有限） |
| **可扩展性** | 高（分层架构天然支持增量修补） | 中（SVD 子空间随任务变化需重新分解） |
| **风险透明度** | 高（20 条缺陷全部列出 + 3 项原理边界声明） | 低（未讨论 SVD 漂移、V_hack 定义完整性等风险） |

**结论**：RLBV v0.4 是一套工程上更成熟、风险更透明的方案，适合直接落地；RLVG 在几何白盒化和计算效率上有独特优势，但在工程闭环（监控、回调、数据管理）方面尚不完整。两者融合可取长补短。
