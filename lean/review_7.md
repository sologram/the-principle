## 六、模型验证审查

### 6.1 canonicalEnv（退化模型）

- **状态**：定义完整，所有 Env 字段均有赋值
- **公理验证**：所有内嵌公理均有 by 证明块
- **潜在问题**：Knows _ _ _ := False 意味着所有系统在所有时刻不知晓任何状态，这使 Free 和 License 成为 Correct 的函数。在此模型中 Correct 恒真（valuationAt 恒 assigned），因此 Free 退化为 ∃ σ, ¬False = True（只要状态非空）。模型是退化的但一致。

### 6.2 nontrivialEnv（非平凡模型）

- **状态**：定义完整，所有 Env 字段均有赋值
- **公理验证**：所有 Env 内嵌公理均有 by 证明块
- **非平凡性定理**：5 个定理验证了自由/秩序/放任/民主/独裁的存在性及互斥性
- **潜在问题**：
  - DescribesCompletely _ _ := True 使公理7 trivially 成立（所有描述都"完全描述"），建议后续引入真正的描述长度比较
  - ParetoEfficient _ := True 使公理5 trivially 成立
  - 这两个设计选择使模型一致性证明过于简单，削弱了模型作为"非平凡见证"的力度

## 七、结构/设计问题

### 7.1 Env 结构体过大

Env 结构体包含 40+ 字段，其中许多是命题类型谓词（如 IsCollective, HasCommitment 等），而非计算性内容。这导致：

- 每个模型需要实现所有字段（包括永远不会用到的）
- 证明脚本冗长（nontrivialEnv 的每个公理证明都需要 cases 或 simp）
- 建议：考虑将正交谓词拆分为独立的 class 或 structure，通过类型类实例组合

### 7.2 ShouldPrune 的语义偏差

纲要原文："必须剪除：不完备的'正确'，不无知的'自由'，不效率的'正义'，无价格的'意义'，以及无目的的'演化'"

代码实现：

```lean
def ShouldPrune (s : E.System) (t : E.Time) : Prop :=
  (¬ Correct E s t) ∨ Order E s t ∨ (Just E s ∧ ¬ E.ParetoEfficient s)
```

差异：

1. 代码仅覆盖 3/5 种剪枝情形
2. Order E s t 作为剪枝条件语义存疑：纲要说"不无知的'自由'"应理解为"声称自由但实际上已知"（即 Free ∧ Knows），但 Free 定义已要求 ∃ σ, ¬Knows，所以 Free ∧ Order 矛盾。代码改用 Order 本身作为剪枝条件，偏离了原文
3. 缺少"无价格的'意义'"和"无目的的'演化'"的剪枝条件

### 7.3 民主四元组缺少互斥定理

认识论四元组、文化实践四元组、科学四元组均有互斥定理，但民主四元组（民主/民粹/专制/独裁）仅有定义，缺少互斥性证明。鉴于其定义依赖于 IsCollective/IsIndividual 的互斥性和 Order/License 的互斥性，这些定理应可直接证明。

### 优先级建议

1. **P0（阻塞性）**：补全公理 1（正确即完备）—— 它是绝对真理定理、科学五定律的推导基础
2. **P1（完整性）**：补全民主四元组互斥定理、ShouldPrune 缺失情形
3. **P2（正确性）**：审查 ShouldPrune 的 Order 条件是否偏离原文语义
4. **P3（工程）**：拆分 Env 结构体，引入类型类组合
5. **P4（扩展）**：形式化爱智慧四定律、民主定理、域外执法定理
